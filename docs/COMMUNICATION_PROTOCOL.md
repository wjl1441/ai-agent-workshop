# 通信协议标准

所有子 Agent 的入参和出参使用统一格式，确保 Supervisor 能精确解析每个子 Agent 的返回结果。

---

## 入参标准（Supervisor → 子 Agent）

通过 `run_skill` 的 `arguments` 参数传递，三段式：

```
任务：<做什么>
数据：<原始数据>
格式要求：<可选>
```

### 示例

```
任务：搜索 RAG 最新进展
数据：（空，搜索不需要额外数据）
格式要求：中文优先
```

```
任务：周报
数据：这周学了 5 天，完成 12 项...（详细数据）
格式要求：简洁风格，不要分段
```

---

## 出参标准（子 Agent → Supervisor）

统一带 `[状态]` 标记，三段式：

```
[状态] 成功 / 无结果 / 错误
[数据] <具体内容>
```

### 三种状态

| 状态 | 含义 | Supervisor 的处理 |
|---|---|---|
| `[状态] 成功` | 正常返回结果 | 正常使用 `[数据]` 中的内容 |
| `[状态] 无结果` | 搜不到 / 数据为空 | 告诉用户"没找到" |
| `[状态] 错误` | 执行出错 / 不理解参数 | 告知用户异常，或尝试替代方案 |

### 示例

**正常返回：**
```
[状态] 成功
[数据] 搜到 3 条结果：
  - 标题：RAG vs Fine-tuning | 来源：xxx | 摘要：xxx
  - 标题：...
```

**搜不到：**
```
[状态] 无结果
[数据] 未找到与"xxx"相关的结果
```

**出错：**
```
[状态] 错误
[数据] 无法识别写作类型，可用类型：周报/笔记/对比报告
```

---

## 为什么需要这个协议

### 之前没有协议的问题

```
Supervisor: "帮我搜一下 xxx"
  search-agent 返回: "搜到了一些结果，第一条是..."
                            ↑ Supervisor 怎么知道搜到了几条？
                              如果没搜到，它回什么？

Supervisor: "写一份周报"
  writing-agent 返回: "# 学习周报（写得还行...）"
                            ↑ 如果写不了呢？它会硬写。
                              Supervisor 感知不到失败。
```

### 加上协议后

```
Supervisor: "帮我搜一下 xxx"
  search-agent 返回: "[状态] 无结果 / [数据] 未找到..."
                            ↑ Supervisor 读到 [状态] 无结果
                              直接告诉用户："没搜到关键词相关结果"

Supervisor: "写一份周报"
  writing-agent 返回: "[状态] 错误 / [数据] 无法识别写作类型..."
                            ↑ Supervisor 读到 [状态] 错误
                              重新整理参数再试
```

**核心价值**：从"猜"变成"读状态标记"。

---

## 当前已对接协议的 Agent

| Agent | 入参格式 | 出参格式 | 状态 |
|---|---|---|---|
| search-agent | 三段式 | `[状态] 成功/无结果` | ✅ 已对接 |
| writing-agent | 三段式 | `[状态] 成功/错误` | ✅ 已对接 |

> 后续新增的子 Agent 必须遵循同一协议。
